## Debugging PyTorch SIGSEGV in Distributed SFT/LoRA Training

Your segmentation fault (SIGSEGV, Signal 11) errors during distributed training with Accelerate and LoRA are occurring during multi-GPU initialization. The training gets approximately 6% through the dataset before crashing, indicating the issue is likely in memory management or NCCL communication setup. Here's a systematic debugging and resolution approach:

### Immediate Quick Fixes to Try First

**Enable cuMem Host Allocation Workaround**[1]

Set this environment variable before launching your training:

```bash
export NCCL_CUMEM_HOST_ENABLE=0
```

Then run your training. This disables CUDA Unified Memory host allocation which has known compatibility issues with certain GPU configurations and NCCL versions.[2]

If this works, you've found the root cause. If not, proceed to the comprehensive debugging steps below.

**Reduce Memory Pressure Temporarily**

```bash
export PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True
```

This helps with memory fragmentation.[3]

### Systematic Debugging Workflow

**Step 1: Isolate Single GPU Training**

First, verify your script works on a single GPU without distributed training:

```bash
python train.py  # No accelerate launch, single GPU
```

If this works, the problem is specific to distributed communication. If this fails too, there's a model-level or data pipeline issue to fix first.

**Step 2: Test with Gloo Backend Instead of NCCL**[4]

NCCL has known issues on certain hardware configurations. Configure Accelerate to use the Gloo backend:

```bash
export NCCL_DEBUG=INFO
export NCCL_DEBUG_SUBSYS=ALLOC
accelerate launch --mixed_precision=bf16 --num_processes=2 --backend=gloo train.py
```

If this works, you have a NCCL compatibility issue specific to your hardware.

**Step 3: Capture Detailed Error Information**

Enable comprehensive NCCL debugging:

```bash
export NCCL_DEBUG=TRACE
export NCCL_DEBUG_SUBSYS=ALL
export CUDA_LAUNCH_BLOCKING=1
accelerate launch train.py 2>&1 | tee training_debug.log
```

This creates a log file showing exactly where the segfault occurs.[5]

### Root Causes and Solutions

**Memory Allocation Issues**[6]

The most common cause is incompatibility between your CUDA version, PyTorch version, and NCCL version. Solutions:

- Check version compatibility: "CUDA runtime version: X.X" from your error logs must align with your NCCL version
- Try the cumem workaround mentioned above
- Reduce batch size or model size to confirm it's a memory issue
- Enable CPU memory offloading in your training config

**P2P Access Problems**[1]

Some GPU topologies don't support peer-to-peer access between devices:

```bash
# Check if P2P is available
nvidia-smi topo -m

# If disabled, try:
export NCCL_P2P_DISABLE=1
accelerate launch train.py
```

**FSDP + LoRA Specific Issues**[7][8]

If using FSDP with LoRA:

- Set `use_orig_params=True` in your FSDP config
- Use `SHARDED_STATE_DICT` rather than `FULL_STATE_DICT`
- Ensure `gradient_accumulation_steps=1` initially (known issue with higher values )[8]
- Disable CPU offloading if enabled, as it can interact poorly with LoRA layer dimensions

- **WSL/WSL2**: NCCL host memory allocation behaves differently. Always use `NCCL_CUMEM_HOST_ENABLE=0` on WSL
- **Cloud VMs**: Check firewall rules and network interfaces aren't blocking NCCL communication
- **Container/Docker**: Ensure `--gpus all --shm-size=16gb` flags are passed to docker run
